AR 寵物召喚：上傳與上架步驟

照順序做就好。第 1、2 步現在就能做；第 3 步以後是上架 Play 商店才需要。

1更新 GitHub 上的 ar-pet

這次的檔案不只一個，結構是這樣：

ar-pet/
├─ index.html            主程式
├─ manifest.webmanifest  App 名稱、圖示（可安裝用）
├─ sw.js                 離線快取（可安裝用）
├─ privacy.html          隱私權政策
├─ delete-account.html   刪除帳號說明頁
├─ js/
│  ├─ config.js          ★ Firebase 設定貼這裡
│  ├─ catalog.js         寵物種類、遊戲數值、商品
│  └─ sounds.js          內建叫聲
└─ icons/                App 圖示
  1. 先貼 Firebase 設定：用記事本打開 js/config.js，把 const firebaseConfig = null; 換成你 11/11 那筆修改裡的整段 const firebaseConfig = { … };。只要這一段，不要複製 import 和 initializeApp 那幾行。
  2. 填聯絡 Email：打開 privacy.html 和 delete-account.html，把 【請填你的聯絡 Email】 換成你的 Email（Google 規定一定要有）。
  3. 到 GitHub 的 ar-pet 儲存庫 → Add file → Upload files，把解壓縮後 ar-pet 資料夾裡面的所有東西（包含 js 和 icons 兩個資料夾）一起拖進去，按 Commit changes。舊的 index.html 會被新的蓋掉。

Firestore 安全規則（一定要換）

飼料數量存在雲端，規則要設定成「使用者只能減少飼料，不能自己加」，不然有人可以改數字變出飼料。

  1. Firebase 主控台 → Firestore Database → 規則 分頁。
  2. 把 firestore.rules 的內容整段貼上，取代原本的全部內容，按 發布。
已知限制：使用者如果刪除帳號再重新註冊，會再拿到 5 包免費飼料。要完全防止，要等之後加了伺服器端的雲端函式。

2建立 wingfeeling.github.io（證明網站是你的）

Android App 會到 https://wingfeeling.github.io/.well-known/assetlinks.json 檢查這個網站是不是屬於你的 App，所以這個檔案要放在網站最上層，要另外開一個儲存庫：

  1. GitHub 右上角 ＋ → New repository。
  2. Repository name 一定要打 wingfeeling.github.io（跟你的帳號名稱完全一樣），選 Public，勾 Add a README file，按 Create repository。
  3. 上傳 index.html（打開 wingfeeling.github.io 會自動轉到 /ar-pet/）。
  4. 點開頭的檔案拖曳上傳會被略過，要用「新增檔案」建立：
    • Add file → Create new file，檔名打 .nojekyll，內容空白，按 Commit。這個檔案讓 GitHub 不要隱藏 .well-known 資料夾。
    • 再一次 Create new file，檔名打 .well-known/assetlinks.json（打到斜線會自動變成資料夾），內容先貼範本，等第 3 步拿到真的內容再換掉。
  5. 到儲存庫的 Settings → Pages，確認 Source 是 Deploy from a branch、分支選 main。大約 1～2 分鐘後，打開 https://wingfeeling.github.io/.well-known/assetlinks.json 看得到內容就成功了。
你原本的 wingfeeling.github.io/ar-pet 網址不會受影響，照常可以用。

3打包成 App（PWABuilder，不用下載軟體）

建議用微軟出的免費網站 PWABuilder，在瀏覽器裡就能打包，不需要安裝 Android Studio。（另一個選擇是 Google 的 Bubblewrap，要在電腦上裝 Node.js 和 Java，比較麻煩。）

  1. 打開 pwabuilder.com，輸入 https://wingfeeling.github.io/ar-pet/，按 Start。它會檢查 manifest、service worker 有沒有問題。
  2. 按 Package For Stores → Android → Generate Package，先按 Options 設定：
    • Package ID：例如 io.github.wingfeeling.arpet。上架後就不能改，想清楚再填。
    • App name：AR 寵物召喚；Launcher name：AR 寵物。
    • Signing key：選 Create new，填你的名字和組織（個人可以填自己名字）。
    • 之後要接付款時，回來勾 Google Play billing（或類似名稱的選項）再打包一次。
  3. 下載的 zip 裡會有：
    • .aab 檔：上傳到 Play 管理中心的檔案。
    • signing.keystore 和 signing-key-info.txt：簽署金鑰和密碼，一定要備份到安全的地方。弄丟了以後就沒辦法更新這個 App。
    • assetlinks.json：把內容貼到第 2 步的 .well-known/assetlinks.json。
  4. 上傳到 Play 之後，Google 會用它自己的金鑰重新簽署。到 Play 管理中心 測試與發布 → 設定 → 應用程式完整性 → 應用程式簽署，複製那裡的 SHA-256 憑證指紋，也加到 assetlinks.json 的 sha256_cert_fingerprints 裡（兩個指紋都要放）。沒做這步，App 上方會出現網址列。

其他問卷

  • 目標對象與內容：建議選 13 歲以上。如果勾了 13 歲以下，會被列入「家庭」政策，限制多很多（登入、付款都有額外規定）。
  • 內容分級：照實填，沒有暴力、賭博等內容，通常會拿到「普遍級／3+」。
  • 廣告：沒有廣告。
  • 應用程式存取權：如果登入後才能用的功能，要提供一組測試帳號給 Google 審查。不登入也能玩，就選「所有功能都不需要特殊存取權」。

5封閉測試（個人帳號必做）

  1. Play 管理中心 → 測試 → 封閉測試 → 建立測試群組，加入至少 12 位測試者的 Gmail。
  2. 上傳 .aab，送審。通過後把測試連結傳給他們，請他們用連結安裝。
  3. 12 位以上測試者要連續 14 天都保持加入測試，之後才能申請正式上架。
在封閉測試時，請特別測這幾件事，App 版跟網頁版有時候不一樣：AR 能不能開啟、Google 登入的視窗能不能正常跳出來並回到 App、麥克風權限。有問題把畫面上的文字截圖給我。

Google 的規定會更新，實際以 Play 管理中心畫面上寫的為準。
